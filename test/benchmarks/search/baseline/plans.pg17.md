## Legend

Each row is one statement a scenario ran, `#` its position in execution order.

- `cost`: Postgres' guess of the work, made before the statement runs (unit: one page read in order). Estimated, not measured: it changes when Postgres picks another plan or the statistics change.
- `blocks`: 8kB pages read, from memory or disk. Measured. The main measure of I/O.
- `rows`: rows passed between all plan steps, over all their repeats. Measured. Not the number of results: it shows extra work inside the plan even when the results stay the same.
- `max_loops`: how often the most repeated plan step ran. Measured. A jump means a step now runs per index row instead of per entity, like an accidental nested loop.
- `filtered`: rows read and then thrown away, by a filter or an index recheck. Measured. Wasted work: high means the index does not narrow the candidates down well.
- `function_calls`: calls to non-builtin functions (such as pg_trgm's similarity or ltree's `ltq_regex`) made row by row. Measured. Calls inside an index search do not count, so 0 means the index does all the work.
