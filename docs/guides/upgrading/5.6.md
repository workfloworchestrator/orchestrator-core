# 5.6 Upgrade Guide

In this document we describe changes to be aware of when upgrading from `orchestrator-core` v5.5 to v5.6.

## About 5.6

This release introduces:
- [SQLAlchemy 2.1 type annotations](#sqlalchemy-21-type-annotations)

## SQLAlchemy 2.1 type annotations

orchestrator-core now depends on SQLAlchemy 2.1, which switched `Select` and `Row` to
[PEP 646](https://peps.python.org/pep-0646/) variadic generics. Several public helpers are
therefore annotated with the new style:

| Public helper | Before (SQLAlchemy 2.0) | Now (SQLAlchemy 2.1) |
|---|---|---|
| `services.subscriptions.select_in_use_by_subscriptions` | `Select[tuple[SubscriptionTable]]` | `Select[SubscriptionTable]` |
| `services.subscriptions.select_depends_on_subscriptions` | `Select[tuple[SubscriptionTable]]` | `Select[SubscriptionTable]` |
| `SubscriptionTable.select_by_product_tag` | `Select[tuple[SubscriptionTable]]` | `Select[SubscriptionTable]` |
| `WorkflowTable.select` | `Select` | `Select[WorkflowTable]` |

The runtime behaviour is unchanged; only the annotations differ. If your own code annotates these
results, drop the `tuple[...]` wrapper (or use `Select[MyModel]`) so it keeps type checking under
SQLAlchemy 2.1. mypy 1.7 or newer is required for the new typing to work.
